The pattern: every control follows one of four shapes

ShapeUse forTodayProposed
Segmented choiceOne of 2 to 4 options (width, colour mode, direction, view, colour emulation)Radio buttons, laid out differently in each blockOne joined strip, current value always readable, arrow keys work like radios
SwitchA behaviour on or off (mirror, sync, axe, Lighthouse, JavaScript)Checkboxes with long labelsLabel left, switch right, one line of hint underneath
Action buttonDoes something once (Go, Log in, Reload, Clear caches)Mixed in with settingsOnly in the top bar or the Tools menu, never inside a settings group
Result tabEvidence you read or fill in (Steps, Matrix, Checks, Accessibility, Environment)Seven sections stacked in a 2,700 px scroll, frames start below the foldTabs in a dock under the frames; each tab shows a count or verdict so you do not have to open it

Rules that make it feel uniform

  • Settings are grouped by the question they answer: Conditions (what is rendered), View (how you compare), Input (how the two sides are driven), Automated checks (what is measured). Results and records live in the dock.
  • Defaults are marked, changes are visible. A group's header summarises its non-default values, a Reset link appears on any changed row, and a strip above the frames lists everything that is not default. This replaces the grey hint text.
  • Frames come first. They fill the window; nothing scrolls the page.
  • Status is never colour alone: every chip carries text or a symbol (Pass, Fail, Not run).
  • Optional extras stay off by default and are remembered in localStorage only, as now. Settings that need the lab browser carry a dashed "lab browser" chip instead of disappearing.
  • Test matrix. Width by colour mode (extendable to direction and forced colours) with a status per cell and an Apply button that sets both frames to that combination, so "what have I covered?" is answered in one glance and the coverage can be saved with the log.
