Changes to Contributed Modules for Extending Accessibility in Drupal

This document explains the redraft of Contributed Modules for Extending Accessibility in Drupal. Project status was checked on July 28, 2026.

Summary

The original page mixed active modules, unsupported projects, generic HTML filters, commercial products, editorial checks, and end-user widgets. It also repeated project-page marketing language without consistently explaining limitations.

The revision:

  • Uses a clear selection policy based on accessibility purpose, supported releases, security advisory coverage, maintenance, and accurate claims.
  • Groups modules by the job they perform.
  • Explains that installing a module does not establish accessibility or WCAG conformance.
  • Distinguishes accessibility barriers, WCAG requirements, automated test rules, and conformance decisions.
  • States that only a smaller deterministic subset of automated rules is suitable for unattended build gates.
  • Requires human judgment for alternative text and other contextual findings.
  • Labels the Siteimprove integration as commercial.
  • Treats presentation controls as optional preferences, not remediation.
  • Removes unsupported projects, promotional scanners, a commercial overlay, generic HTML sanitizers, and modules without a clear current accessibility function.
  • Adds a July 2026 review date while directing readers to project pages for current status.

Detailed project decisions

Project Decision Reason
A11Y: Form helpers Retained and revised. It has a supported stable release, security advisory coverage, and a clear form-accessibility purpose. The new description adds testing limits.
Able Player Retained and revised. It is current and security-covered. The new text explains that an accessible player does not replace captions, transcripts, audio descriptions, or other required alternatives.
Block ARIA Landmark Roles Retained and revised. It has a supported stable release and security coverage. The new text prioritizes native HTML and warns against redundant roles, duplicate labels, and inaccurate landmark structure.
CKEditor Abbreviation Removed. The project is minimally maintained. Adding an abbreviation element and title does not by itself provide a clear accessibility improvement, and the feature is too narrow for this curated list.
Disclosure Menu Retained and revised. It has a supported stable release, security coverage, and a specific keyboard-navigation purpose. The new text requires testing in the finished theme.
AI Image Alt Text Retained with stronger limits. The module includes an editor approval workflow. The revision describes generated text as a proposal and adds checks for image purpose, human review, privacy, licensing, data handling, and cost.
Alt Text Validation Retained and revised. It has a supported stable release, security coverage, and a clear editorial function. The new text explains that rule compliance cannot determine whether alternative text is appropriate.
Analyze Removed. The current project provides a generic content-analysis API and plugins for content statistics, links, search, marketing, sentiment, and security. Its project category is not sufficient evidence of an accessibility check, and the current module list does not identify a specific accessibility analyzer.
Automatic Alternative Text Removed. Automatically filling an empty alternative-text field can hide the need for an author to decide whether an image is informative, functional, complex, or decorative. The retained AI Image Alt Text module has an explicit human approval step.
Editoria11y Accessibility Checker Retained and revised. It is actively used, current, security-covered, and designed for editorial feedback. The new description avoids implying that its automated checks form a complete audit.
htmLawed Removed. It is an HTML policy and security filter, not an accessibility evaluation or remediation module. Its project page also warns that the bundled upstream library might not be current.
HTML Purifier Removed. It is a minimally maintained security filter. Valid or sanitized HTML can still contain accessibility barriers, so its inclusion could confuse markup policy with accessibility.
Node Link Report Retained and revised. It has a supported stable release and security coverage. The new text describes its accessibility checks as limited and requires contextual review.
Siteimprove Retained and labelled commercial. The maintained integration can bring results into the editorial workflow, but it requires a separate commercial service. The revision states that automated results do not establish conformance.
Accessibility menu Retained and revised. It has a supported stable release and security coverage. The new text requires testing the control and every available presentation combination.
All in One Accessibility Removed. This commercial overlay loads third-party code, promotes automated enhancements and legal or standards alignment, and includes subscription, agency, and affiliate offers. Its own limitations say it is not a replacement for manual remediation. A Drupal documentation shortlist should not present an overlay as a route to accessibility.
Civic Accessibility Toolbar Removed from the shortlist. The project is in maintenance-fixes-only status. Its contrast and font controls overlap with the retained, currently developed presentation-control options.
Fluidproject UI Options Retained and revised. It has a current stable release and security coverage. The new text adds theme-integration testing and a cookie privacy consideration.
High Contrast Removed. The project has no supported stable release and does not list support for Drupal 11.
Style Switcher Removed from the shortlist. The project is minimally maintained. Its function overlaps with the retained presentation-control options.
Text Resize Removed from the shortlist. The project is in maintenance-fixes-only status. Modern sites must support browser text resizing, zoom, and reflow without requiring a site-specific control.
SkynetAccessibility Scanner Removed. The project is not covered by Drupal’s security advisory policy. Its project page makes broad standards and legal-compliance claims and promotes a time-limited commercial trial and affiliate program.
Accessibility Scanner Removed. The project is not covered by Drupal’s security advisory policy and is marked “No further development.”

Structural and language changes

Changes to the page as a whole
Area Change Reason
Introduction Replaced the general outdated-project note with concrete checks for support, maintenance, security, dependencies, and testing. Readers need actionable selection criteria. A blanket warning does not explain how to choose a module responsibly.
Project status Added a review date and made project pages authoritative for current status. Release and maintenance information changes more often than documentation pages.
Organization Replaced “Core Improvements,” “Quality Assurance,” “End-user Personalization,” and “Experimental” with task-based sections. “Core Improvements” could be confused with Drupal core, while “Experimental” mixed project maturity with unsupported and commercial products.
Automated checks Added the relationship between barriers, WCAG requirements, tool rules, and conformance decisions. A scanner tests only selected conditions. A smaller deterministic subset can run unattended without an unacceptable risk of false positives. Other findings need human judgment.
Artificial intelligence Reframed generated alternative text as an editor-reviewed proposal and added vendor checks. A model cannot determine the author’s intended meaning from pixels alone. External processing can also introduce privacy, licensing, data-handling, and cost concerns.
Presentation controls Reduced the list and added a warning that controls are optional preferences rather than remediation. Every version of the interface still needs accessible design, content, and code. Browser zoom, reflow, forced colors, and user style sheets must continue to work.
Maintenance guidance Added criteria for adding and removing projects from the page. A maintained policy is more durable than an unqualified accumulation of project links.
Voice Rewrote descriptions in clear, direct Drupal.org language instead of copying promotional project text. Drupal’s content style guide calls for simple, concise, honest, approachable language and specific naming of modules.

Claims not made

The revision does not claim that:

  • Installing a module makes a site accessible or WCAG-conformant.
  • Inclusion on the page is an endorsement by the Drupal project.
  • Valid or sanitized HTML is necessarily accessible.
  • A toolbar, overlay, or alternate presentation repairs underlying barriers.
  • Artificial intelligence can determine appropriate alternative text without an author’s judgment.
  • An automated scanner can identify every barrier or decide conformance.
  • Every automated rule is reliable enough for an unattended build gate.
  • A commercial service replaces a defined accessibility review process.
