Contributed modules can support accessible development, authoring, and testing. Installing a module does not make a site accessible or establish conformance with the Web Content Accessibility Guidelines (WCAG).

Before selecting a module, review its supported Drupal versions, maintenance status, security advisory coverage, dependencies, and issue queue. Test the module with your theme, content, keyboard controls, and supported assistive technologies. Inclusion on this page is not an endorsement by the Drupal project.

This list was reviewed in July 2026. Project pages are the authoritative source for current release and support information.

Implementation and authoring

A11Y: Form helpers

The A11Y: Form helpers module adds readable inline error messages and supports HTML autocomplete attributes. These features can improve form completion, but they do not correct every form barrier. Test labels, instructions, validation, error recovery, focus, and keyboard operation together.

Able Player

The Able Player module integrates an accessible media player for HTML audio and video. A player is only part of accessible media delivery. Provide the captions, transcripts, audio descriptions, and other alternatives required for the media.

Block ARIA Landmark Roles

The Block ARIA Landmark Roles module lets site builders assign Accessible Rich Internet Applications (ARIA) landmark roles and labels to blocks. Use native HTML landmarks where possible. Do not add redundant roles or duplicate labels, and confirm that landmarks describe the page structure accurately.

Disclosure Menu

The Disclosure Menu module adds buttons that open and close submenus. This can give keyboard users control over whether they enter a submenu. Test the finished navigation with a keyboard, at different zoom levels, and with supported screen readers.

Editorial quality assurance

Automated checks can find some barriers by applying rules to a limited set of testable conditions. They cannot determine whether a page or site conforms to WCAG. Only a smaller set of deterministic rules is suitable for unattended build gates. Findings that require context or judgment need human review.

Alt Text Validation

The Alt Text Validation module reports on image alternative text and can warn authors or prevent saving when configured rules fail. A passing rule does not mean the text is appropriate. Authors must decide whether an image is informative, functional, complex, or decorative, then provide the right alternative.

Editoria11y Accessibility Checker

The Editoria11y Accessibility Checker module marks selected content issues on rendered pages and previews. It gives authors explanations, review prompts, and issue reports. Treat its results as editorial assistance, not a complete accessibility audit.

Node Link Report

The Node Link Report module checks links on content pages. It reports broken and redirected links and flags a limited set of link-name and image-alternative issues. Review each result in context and include broader link and navigation testing in your accessibility review.

AI Image Alt Text

The AI Image Alt Text module can propose alternative text using a configured vision model. Generated text is a starting point, not an authoritative description. An editor must determine the image’s purpose and approve or replace the suggestion. Review the model provider, data handling, privacy, licensing, and cost before sending images to an external service.

Commercial integration

Siteimprove

The Siteimprove module displays results from the commercial Siteimprove service during content editing. A separate subscription is required. The integration can support an established review process, but automated results do not establish WCAG conformance.

Optional presentation controls

Some sites provide controls for font size, spacing, contrast, or other presentation preferences. These controls may help some users, but they do not repair inaccessible content or components. Do not use a toolbar or overlay as a substitute for accessible design and code. Every available presentation must be tested. Browser zoom, text resizing, reflow, forced colors, and user style sheets must continue to work.

Accessibility menu

The Accessibility menu module provides controls for contrast, font size, line height, letter spacing, and font style. Confirm that the menu itself is accessible and that each combination of settings preserves content and functionality.

Fluidproject UI Options

The Fluidproject UI Options module provides controls for text size, line height, font, contrast, and link presentation. It stores user preferences in cookies. Test its theme integration and account for those cookies in your site’s privacy and consent practices.

Keeping this list current

Add a module when it has a clear accessibility purpose, a supported stable release, Drupal security advisory coverage, and accurate documentation of its scope and limits. Label commercial dependencies clearly. Do not include a project that claims installation, automation, artificial intelligence, or an overlay can make a site conform to WCAG.

If a listed project becomes unsupported, loses security advisory coverage, or no longer serves an accessibility purpose, remove it from this page. Always check the project page before using a module.
