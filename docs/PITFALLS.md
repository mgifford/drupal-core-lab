# Known pitfalls (each cost real time; check here before debugging)

Moved out of `AGENTS.md` on 2026-10-15 so that file, which every session loads, stays short (AI-usage option C: scope the starting context). The text is unchanged except where noted.
Search it for the error text first: `grep -n -i "<text>" docs/PITFALLS.md`.


| Symptom | Cause and fix |
|---|---|
| `ddev-router failed to become ready` | DDEV's shared router is flaky. Re-run: `setup.mjs` and `lab-env.mjs start` retry and resume. |
| `docker-compose build failed: Dockerfile:51` at `apt-get install ... chromium=143...`, then `E: Version '143...' was not found` and `Unable to locate package libdav1d6` (2026-11-05) | Docker reused a cached, empty `apt-get update` layer: `snapshot.debian.org` dropped a fetch once, `apt-get update` still exited 0, and every build of the same Dockerfile now fails the same way. The pins themselves resolve (checked in a fresh container). `setup.mjs` now runs `ddev debug rebuild` once when it sees this; by hand: `cd envs/<env> && ddev debug rebuild`. The pinned chromium and the dated Debian snapshot come from the add-on's `web-build/Dockerfile.chromium`; `setup.mjs` pins the add-on release (`tools/compare/ddev-build-failure.mjs`). |
| Loading box: both sides "unreachable: Client network socket disconnected before secure TLS connection was established"; frames: "drupal-compare-before.ddev.site unexpectedly closed the connection" | The DDEV router accepts connections on port 443 but drops them before TLS, for every `*.ddev.site` site at once. Seen on a Mac on 2026-10-19 after building a third environment; re-running `lab-env.mjs start` did not help. Fixed by resetting DDEV (stops all projects and the router, keeps all data): `ddev poweroff`, then `node scripts/lab-env.mjs start <slug>`. If it comes back, check that no other app listens on localhost:443 (`netstat -an \| grep LISTEN \| grep '\.443 '` shows only `*.443`). |
| Frames blank, 502, `ECONNRESET` | Sites still starting, or the router reset plain HTTP. The proxies use HTTPS to the router (port 443); the viewer shows a "still loading" dialog and recovers. Check `node scripts/doctor.mjs <slug>`. |
| "No space left on device", odd failures | Disk. `doctor` shows free space. Free it: delete an unused variant (`lab-env.mjs delete <slug> --yes`), `docker builder prune`, remove `~/Library/Caches/ms-playwright` (then `cd tools/playwright && npx playwright install chromium`). |
| A "fix" check fails on both sides | Script-generated clicks do not trigger focus behaviour. Use trusted input (a real click, or Playwright `click()`); Mirror replays script clicks, so turn it off for the final step. |
| `ddev phpunit` errors before any assertion | `core/.env` missing; `setup.mjs` copies it from `.ddev/core-dev/.env`. |
| Firefox will not launch under Playwright here | Recorded as blocked in COVERAGE, never as a pass. |
| `fetch` to a DDEV site ignores a `Host` header | Use `node:http`/`https` (see `envFetch` in `tools/compare/lib.mjs`). |
| `ddev describe` freezes the viewer | It is synchronous; use the cached/async `envInfoAsync`. |
| macOS: no `timeout`; zsh does not word-split `$var` | Use real exit codes; run multi-word variables through `bash`. |
| The built-in browser pane shows blank frames or `ERR_BLOCKED_BY_CLIENT` | It blocks cross-site frames and requests to some hosts. Verify with Playwright (`tools/playwright/mirror-drag.mjs` is a model), not the pane. |
| Adding a language with a recipe crashes (`setWeight() on null`) | A recipe that installs the Language module does not create its locked languages (und, zxx). Use `scripts/lab-site.sh language <env> <code>` (API script `scripts/add-language.php`); it also sets the `/<code>` prefix. |
| Disk tight | `node scripts/lab-env.mjs disk` shows what uses space (each environment is about 630 MB, 393 MB of it `core/node_modules`; site data is under 10 MB). `trim all --deep` frees the node_modules; `reset` costs no disk. |
| Disk almost full (under 1 GB) | Regenerable caches first: `npm cache clean --force`, `rm -rf ~/.npm/_npx`, `docker builder prune -af`. Then see the disk row above. Check what is big with `du -sh ~/.cache/* ~/.npm`. |
| `css-build.mjs` says BLOCKED, or `yarn: command not found` | The Yarn core pins is not on the PATH. The script uses Corepack's Yarn through a shim (and installs core's own `node_modules` from its lockfile when missing, `--no-install` forbids that); if neither Corepack nor network is available the result is BLOCKED, never an approximation. `FAIL ... stale` means the `.css` really differs from what core's build makes: rebuild it (`--build`, or `--build --corrective` for an imported patch). Core's CSS check passing says nothing about accessibility. |
| Lint fails every JS and CSS check, or says a `.pcss.css` "does not match" | A tool did not run (usually Yarn: core pins `yarn@4` and a global Yarn 1 refuses). `scripts/lint.mjs` now reports this as ERROR and uses Corepack's Yarn. If Corepack cannot reach repo.yarnpkg.com, set `COREPACK_NPM_REGISTRY=https://registry.npmjs.org`. |
| `lab-env.mjs stop` (or `trim`, `delete`) printed nothing and nothing stopped | Run from a git worktree (`.claude/worktrees/<name>`): environments live in the main checkout's `envs/`. Fixed 2026-10-14: it now exits 1 and names the main checkout to run it from. |
| Lint: "Could not prepare the file list: ... GIT_DIR: unbound variable", or PHPStan "crashed because it reached configured PHP memory limit" | Fixed 2026-10-14. `ddev exec` re-quotes separate arguments, so `ddev exec bash -c '<script>'` expands variables too early; `scripts/lint.mjs` passes the script as one argument. It also passes core's `--memory-unlimited` to the check script, and reports a PHPStan memory crash as ERROR (the tool did not run), not FAIL. |
| Before is not pristine | Only if the variant lists `before.patches` (a declared test-support change, e.g. #3604037's form_test page). |
| `try-tests` reports "before tracked files changed during the run", or a baseline's `default_admin` theme has unrelated edits/deletions | An explicit two-way `ddev mutagen sync` pulled stale container files into the Before checkout (2026-11-24). Fixed: `try-tests` no longer flushes Mutagen; it waits for the copied files to appear in the container and compares tracked **and untracked** files. Restore tracked files with `git -C envs/<env> restore --worktree -- .`; remove only the stale untracked theme assets, then copy the clean host theme into the container (`docker exec ... rm -rf /var/www/html/core/themes/default_admin`; `docker cp .../default_admin ...:/var/www/html/core/themes/`) and flush. Do **not** use `ddev mutagen reset` while the pair is meant to stay up: it removed the containers (2026-11-24; a normal restart recovered the site). |

| `BLOCKED: <env> does not match its patches` or `... its contrib modules/projects and patches` (setup, exit 4; or a run) | Patches are tracked by content (`tools/compare/patch-state.mjs`; contrib projects and their patches in `tools/compare/contrib-state.mjs`): the patch file changed (a new MR push), a variant's contrib commit changed, or a patched file was edited. Nothing was changed. `setup.mjs <slug> --refresh-patches` restores the files the patches touch (your edits in them are saved to `lab-patches/backup-*.diff` in the checkout's git dir) and applies the current patches. |
| `BLOCKED: the environments of <slug> are not in the state the variant asks for` (setup exit 4, a run, or listed under `lab-env.mjs status`) | Observed against requested (`tools/compare/env-state.mjs`): Before and After on different base commits, a pinned variant's commit the environment is not at, or the recipe applied to a site is not `recipes/<name>` as it is now. Nothing was changed. Base or pin: `lab-env.mjs delete <slug> --yes`, then `setup.mjs <slug>` (a rebuild is the only safe move to another base). Recipe: `lab-env.mjs reset <slug> --yes` (a plain `setup.mjs` rerun refuses to apply a changed recipe on top of an existing site, because recipes never uninstall). A missing second environment is created at the first one's commit, not at the newest core. |
| `BLOCKED: the Before environment (<env>) has tracked changes its variant does not declare` (a run); `WARNING: <env> is a baseline and has tracked changes ...` (setup) | A baseline is never edited (`AGENTS.md` rule 1). Setup warns and carries on; a run refuses, because evidence from a Before that is not the pristine commit is not evidence of the change. Revert: `git -C envs/<env> checkout -- <file>`; or, if the change is meant (a test-support change that must be on both sides), declare it as `before.patches` in the variant. `lab-env.mjs status` lists such baselines. Edits outside the patches on the After side only warn, and a run records them in `results.json` (`patchState.after.outside`). |
| `could not write DDEV config file ...: project repro-<env> project root is already set to <other checkout>` (setup, building a variant in a second checkout or worktree) | DDEV project names are global to the machine, and an environment of that name already exists in another checkout. Use a variant with its own environment names (see `3618230-pilot` in `reports/issues/3618230/variants.json`), or work in the checkout that owns the environment. Setup removes nothing; remove the half-made worktrees it printed. |
| `BLOCKED: <slug>: after lists no patch and no contrib patch, so After would equal Before` (setup, exit 4; a run; `selftest`) | The variant's After has nothing to test (`tools/compare/change-under-test.mjs`). List the patch, or set `"authoring": true` in `after` while one is being written (`scripts/capture-patch.mjs`). |
| `selftest`: `N changed patch file(s) since origin/main without a record` | A file under `reports/issues/*/branches/` differs from the base (an auto-fix, a refresh or a person changed it). Record who and why: `node scripts/patch-change.mjs record <patch> --by "<who>" --reason "<why>"`; it keeps the original in `original-patches/`. `new-issue.mjs --refresh` records its own changes. A skipped check means origin/main is not fetched (`git fetch origin`); that is not a pass. |
| `lint.mjs --contrib` says `NOTHING CHECKED` | The contrib patches change no PHP-family file, so PHPCS had nothing to run on. The other file types are listed as not checked; that is not a pass. |
| `PHP Fatal error: Failed opening required '.../vendor/autoload_runtime.php'` (`core/scripts/dr`, outside DDEV) | Composer disables plugins when it runs as root, so `symfony/runtime` never wrote the file. In a throwaway checkout: `COMPOSER_ALLOW_SUPERUSER=1 composer dump-autoload`. |
| `curl: (56) CONNECT tunnel failed, response 403`, or `getaddrinfo ENOTFOUND www.drupal.org` (a Claude Code cloud session) | The session's network policy refuses drupal.org and git.drupalcode.org. Core comes from the GitHub mirror (`--core-url`); the issue and MR cannot be read until the owner allows those hosts. Say so; do not review from a search summary. |
| `core/scripts/dr user:login` prints its usage, or a link for the wrong host | The option is `--url=<site URL>` (and `--uid=1`), not `--uri`. |
| A shell or monitor dies or never ends after `pkill -f` / `pgrep -f` | The pattern also matches the command line of the shell or loop that runs it. Keep the PID (`$!`) and `kill` it. |
| Every page redirects to `core/install.php` saying "Drupal already installed" (a site served with `php -S`) | The SQLite path in `settings.php` is relative (`sites/default/files/.sqlite`) and `php -S` was started from another folder. Start it from the Drupal root: `(cd <root> && exec php -S 127.0.0.1:<port> .ht.router.php) &`. |
| `error: Your local changes to the following files would be overwritten by merge: tools/playwright/node_modules` (a pull), or `test-mr` says `setting them aside with git stash would delete tools/playwright/node_modules/` | One-time migration (2026-11-27). The symlink `tools/playwright/node_modules -> ../../../../../tools/playwright/node_modules` was committed on 2026-11-25 (a `.gitignore` rule with a trailing slash does not match a symlink) and is now untracked. A checkout where `npm ci` replaced it with a real folder shows ` D tools/playwright/node_modules`. Run `git rm --cached tools/playwright/node_modules` (it changes only the index; the installed folder stays), then pull. **Do not** `git stash`, `git checkout -- tools/playwright/node_modules` or let an older `test-mr.mjs` update the checkout first: they restore the symlink and delete the folder's contents, which no stash keeps (tested in `tests/lab/deps.test.mjs`). |
| `npm warn reify Removing non-directory .../tools/playwright/node_modules` | The same committed symlink, on a checkout that has not pulled the fix: npm replaced it with a folder. Expected once; see the row above. |
| `Error [ERR_MODULE_NOT_FOUND]: Cannot find package 'jsdom'` (or `'@guidepup/virtual-screen-reader'`) imported from `.../tools/playwright/lib/unpublished-speech.mjs`; selftest: `packages the unit tests load ... FAIL` | The static selftest's packages are not installed in this checkout (a fresh clone or a worktree). `node scripts/deps.mjs check --for=selftest` names them and the fix: `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm ci --prefix tools/playwright` and `npm install --no-save --prefix tools/compare/.deps js-yaml@4`. In a secondary worktree, `node scripts/deps.mjs link` reuses the primary checkout's trees instead. No browser download is needed for the static selftest. |
| `deps.mjs`: `resolved from /Users/<you>/node_modules/<package>, not from tools/compare/.deps/node_modules` | A `node_modules` folder above the lab (here a stray `lighthouse` 2.9.4 in the home folder, 2026-11-27) answered Node's module resolution because the lab's own folder lacks the package. The lab's loaders do not look there, so it counts as missing; install it where the fix line says. |
| `npm warn EBADENGINE Unsupported engine { package: 'jsdom@31.0.1', required: { node: '^22.22.2 \|\| ^24.15.0 \|\| >=26.0.0' }, current: { node: 'v22.21.1' ...` | The locked jsdom declares a newer Node.js than this machine's. The selftest's speech tests still passed on 22.21.1 (2026-11-27), so `deps.mjs` and `doctor` report it as a WARN, not a failure. Upgrade Node.js inside the declared range when you can. |
| `git merge-base <local> <main>` in `envs/core.git` prints nothing (exit 1), so a branch looks unrelated to core, or behind/ahead counts are missing | The shared clone is shallow (`setup.mjs` fetches depth 1, `new-issue.mjs` depth 300): history stops at the commits listed in its `shallow` file, and `merge-base` cannot see past them. That is unknown ancestry, not unrelated history: never `--allow-unrelated-histories`. `node scripts/prepare-push.mjs <nid>` reports it as NEED and lists the minimum fetch, for named refs only (`--shallow-since=<day before the base or boundary>` for core's branch, `--deepen=<n>` for a branch cut short inside its own commits); `--fetch` runs it. Do not `--unshallow` (all of core's history), and do not pass a LATER `--shallow-since` to a ref that already reaches further back: it shortens that ref's history (measured 2026-11-27). |
| `git diff --check` (or an editor, or a pre-commit hook) reports `trailing whitespace` on lines of a stored `reports/issues/*/branches/*.patch` that are a lone space | A unified diff writes an EMPTY source line as a context line holding one space: patch syntax, not whitespace in the source. Checking the .patch file is the wrong test. `node scripts/patch-validate.mjs <patch> --base <rev>` applies it in a temporary index and runs `git diff --cached --check` on the RESULTING source, which judges only lines the patch adds. Never strip those spaces from a stored patch: it is evidence (AGENTS.md rule 13; a corrected version is recorded with `patch-change.mjs record`). |
| `fatal: cannot use bare repository '.../envs/core.git' (safe.bareRepository is 'explicit')` (setup, new-issue, lab-env, try-tests, contrib projects) | Agent shells set `GIT_CONFIG_PARAMETERS='safe.bareRepository=explicit'` (the Claude desktop terminal does, 2026-11-27): git then refuses to find a bare repository from `-C <dir>` or the working folder. Fixed 2026-11-27: the lab names its shared clones with `--git-dir=<bare>`, which that setting allows. Do not unset the variable (it is a protection); in your own commands use `git --git-dir=envs/core.git ...` instead of `git -C envs/core.git ...`. |
| selftest: `static checks touched no live tool or network (hermetic) FAIL: ... ddev list -j`; a test prints `HERMETIC: the static self-test does not run ddev (called: ddev list -j)`, `refused a connection to <host>:<port>` (code `EHERMETIC`) or `fatal: transport 'https' not allowed` | Since 2026-11-27 the static unit tests run hermetically (`tools/compare/hermetic.mjs`). A test, or a script it starts, reached a real tool, a remote host or a remote git URL. Give it a stand-in (`standIn(bin, 'ddev', { stdout, status, log })` first on PATH), a server on 127.0.0.1, a local git repository, or a flag that skips the network step (`setup.mjs --skip-pin-check`). Before this, `tests/lab/test-mr.test.mjs` asked the real DDEV and failed whenever another lab copy held `drupal-compare`, and the `setup-*` tests ran `git ls-remote` against GitHub. Do not stop or unlist DDEV projects to make a test pass. |
| selftest says a test FILE failed with only `error: 'test failed'` (node's `ERR_TEST_FAILURE`), e.g. `not ok 55 - tests/lab/unpublished-speech.test.mjs` | The file could not load; node prints the real exception (here `Error [ERR_MODULE_NOT_FOUND]: Cannot find package '@guidepup/virtual-screen-reader'`) as `# ` lines before the file's `# Subtest:` line, and the selftest summary used to drop them. Since 2026-11-27 `tools/compare/test-output.mjs` keeps them: the row says `[MISSING_DEPENDENCY] ... (file did not run)`, the missing package, the importing file, `rerun: node --test <file>` and the fix. All failures, as JSON: `.lab-cache/selftest-last.json`. |
| selftest: `[PERMISSION] ... listen EPERM: operation not permitted 127.0.0.1` or `connect EPERM 127.0.0.1:<port>` | The process may not open local ports: a sandbox (a Claude Code Bash sandbox without `allowLocalBinding`) forbids it. Not a lab failure. Run the selftest where local ports are allowed (a terminal tab, CI) and report the sandbox limit rather than changing the test. |
| `try-tests`: `IDENTITY MISMATCH: the site that would run the tests is not the checkout the variant names, so no test result is reported.` with `DDEV answered from <dir> with project <other> at <other dir>, not this folder` | DDEV 1.25 sends a command run in an unregistered folder to the registered project around it (the nested-project fallback), or the project name belongs to another checkout. A PHPUnit run once "passed" this way against another issue's installation (2026-11-26). Since 2026-11-27 `try-tests` checks before it copies anything. Register the folder as the message says (`cd <dir> && ddev config --project-name=repro-<env>`), or run from the checkout that owns the environment; then `node scripts/lab-env.mjs start <slug>`. |
| `try-tests`: `the web container's copy differs from this checkout for core/lib/Drupal.php ...` or `<url> did not serve a file written into <dir>` | The container or the web server holds another installation's files, or Mutagen has not synced (`ddev mutagen status`, wait, rerun). Do not force a run: a result from those files is not evidence about this checkout. The HTTP check writes `sites/default/files/.lab-identity-<random>.txt` (site data, removed at once) and runs only for Functional, FunctionalJavascript and Build tests. |
