Drupal status messages: every type, its role, and why

Draft, AI-assisted, read from Drupal core main (92e5c3a30476, 2026-11-18). The boxes below are visual replicas with no live role, so opening this page announces nothing. The real markup is shown under each one. Written reference: STATUS-MESSAGES.md.

Status message

Status message

The configuration options have been saved.

<div role="status" aria-label="Status message">
  <h2 class="visually-hidden">Status message</h2>
  The configuration options have been saved.
</div>

Why role="status": a confirmation should be heard, but never cut off what the person is already hearing (polite live region, WCAG technique ARIA22).

Warning message

Warning message

Cron has not run recently.

<div role="alert" aria-label="Warning message">
  <h2 class="visually-hidden">Warning message</h2>
  Cron has not run recently.
</div>

Why role="alert": core treats a warning like an error because it asks for attention now (assertive live region, technique ARIA19).

Error message

Error message

The username field is required.

<div role="alert" aria-label="Error message">
  <h2 class="visually-hidden">Error message</h2>
  The username field is required.
</div>

Why role="alert": a failed action must be heard when it happens, without moving focus (WCAG 2.2 SC 4.1.3 Status Messages).

Variants

  • Default Admin uses the same roles, but names the box from its visible heading (aria-labelledby on the h2) and adds a Hide button.
  • Messages added by JavaScript (Drupal.Message.add()) get the same role and aria-label, and also call Drupal.announce(): assertive for warnings and errors, unless a priority is given. announce: '' turns that call off.
  • More than one message of a type share one box, as a list.

Limits

  • Messages present at page load are not spoken the same way by every screen reader.
  • Several alert boxes at once are announced one after another.
  • This page shows what the templates do. It is not a screen-reader test and says nothing about a theme's colours or sizes.
