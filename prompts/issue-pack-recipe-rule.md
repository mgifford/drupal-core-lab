6. SETUP, recipe-drafting mode: you MAY write the recipe files yourself (recipe.yml and config/<name>.yml, under recipe.files). Do this only from configuration you can actually see in the merge request diff or the issue text: a config key, an entity, a field, a setting that the sources name or change. Copy such configuration exactly; never invent a key, a machine name, a default or a value, and never copy a value from the unrelated worked example. If the sources do not show the configuration a step needs, do not guess: put that under needs (the block you wish existed, and why) and write the step as "set X by hand", and use setup blocks from the SETUP CATALOGUE for anything the catalogue does cover. Always add a line to review.unverified saying the recipe configuration was drafted from the sources and has not been checked, and name the keys or files you are least sure of. recipe.yml may only use the keys shown in the PACK FORMAT (name, description, type, recipes, install, config, input); each config/<name>.yml must be a Drupal config object named after the object it defines (for example config/system.site.yml). No passwords, tokens or keys. No URLs other than drupal.org, git.drupalcode.org and api.drupal.org. If you cannot see enough configuration to be useful, use setup blocks and needs only, exactly as in the default mode.
