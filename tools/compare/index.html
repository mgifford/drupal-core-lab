      How checks are judged

      After the last step, press Run checks. Each check runs inside both frames and says Pass or Fail against what is expected. The rule: a fix check should fail on Before and pass on After; a regression check should pass on both; a precondition must pass on both or nothing else means anything.

      Accessibility, live (axe-core)

      What this shows

      Turn it on under Audits. axe-core runs in both frames after every page load and after interactions. Because both frames are driven the same way, a difference means the change affects accessibility. "Violations" are elements axe flags as failing WCAG A/AA rules. Automated checks find only a subset of problems; they do not replace a keyboard and screen-reader test.

      Lighthouse

      What this shows

      Turn on background audits under Audits. Lighthouse runs in its own headless Chrome and audits the page as it loads, logged in. It does not see states you reach by clicking (for example an error summary after Save) and takes about 10 seconds per site. Accessibility and best-practice audits are shown by default; use axe for live, interactive checking.

      About this viewer

      Mirror repeats real clicks, typed text, checkboxes and selects in the other frame to save setup time. It does not mirror the keyboard (Tab, Enter, focus), because script-generated key events do not behave like real ones. Do the final keyboard check in each frame yourself.
