      Lighthouse (optional, in the background)

      Lighthouse runs in its own headless Chrome and audits the page as it loads, logged in. It does not see states you reach by clicking (for example an error summary after Save) and takes about 10 seconds per site. Accessibility and best-practice audits are shown by default; use axe above for live, interactive checking.

      Accessibility, live (axe-core)

      axe-core runs in both frames after every page load and after interactions (clicks, focus, changes to the page). Because both frames are driven the same way, a difference means the change affects accessibility. "Violations" are elements axe flags as failing WCAG A/AA rules. Automated checks find only a subset of problems; they do not replace a keyboard and screen-reader test.

      The two frames stay in step, so you can confirm the change by eye. Do the steps, click the "URL alias" link yourself in each frame (Mirror off), then answer for each side. Your answers are compared with what is expected and saved in the downloaded log. This does not replace testing with a keyboard and a screen reader.

      Checks

      After the last step, press Run checks. Each check runs inside both frames and says Pass or Fail against what is expected. The rule: a fix check should fail on Before and pass on After; a regression check should pass on both; a precondition must pass on both or nothing else means anything.
