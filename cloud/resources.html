Summary

Host capacity (sampled)

Point-in-time samples from the same checks as scripts/preflight.mjs, collected on demand. The level uses the conservative build/run thresholds. This is not a live monitor, and a gap between samples is not proof of idle time.

Filter

Filters apply to the grouped public rows below. The task count in the cards is for the whole period when a filter is active; token and cost values are filtered.

Energy estimate

Estimated, not measured: a client-reported cost multiplied by a published CLEER energy-per-dollar intensity. It covers remote inference only. How CLEER is used and what it withholds.

Attribution quality

These are independent measures, not a single quality score. Unknown activity is a measurement gap, not waste; a missing Drupal issue is a separate attribution dimension. Figures are for the whole period, not the filtered rows.

Unknown activity by reason

Every Unknown event carries a reason code where the evidence supports one. Model-only requests have no tool invocation; compound commands could not be resolved to one purpose; unrecognized commands need a registry rule or a narrower call.

Request reconciliation

A session is counted from request events only when the request token sum equals the session sum. A mismatch keeps the session total and marks the request rows uncounted; it is reported, never silently adjusted.

Task effectiveness

Only explicitly declared tasks appear here. A task key is a hash of a local task id; descriptions, evidence paths and session names stay local. A completed claim is not a verified outcome.

Infrastructure efficiency (sampled)

Container samples only; this is a historical snapshot, not a live view. CPU-seconds are derived from Docker's sampled percentage over the sample interval, and memory is container usage. Mutagen file counts, Chrome on/off and Docker disk are local-only: run node scripts/lab-env.mjs resources.

Code exploration

Exploration is a legitimate deliverable. Repeated lookups and loops are diagnostics for investigation, not automatic findings of waste: a file may have changed, a test may have failed, or a new task may need the same evidence. Lookup targets remain local.

Repeated operations

A repetition means the same measured command, revision, patch, environment and result signature. A repeated success may be a deliberate repeatability check; a repeated failure may be a real iteration. Inspect before calling either waste.

Prompt and artifact provenance

Metadata only by default: sizes, purpose, content types, fingerprints and artifact references. Prompt text, attachments, local paths and fingerprints are never published. A reference does not prove that a model received or read an artifact.

Tokens by category

Provider-reported token categories for the filtered rows. Cache reads are the prompt context re-read on later calls; the categories are additive provider fields, not independent work.

Data quality

A dash means missing or unavailable, never zero. Provider-reported, measured, derived and estimated values are kept separate.

Possible opportunities

These are deterministic observations from the recorded measurements. They are possible inefficiencies, not confirmed waste. Complex accessibility work may legitimately consume substantial resources.

Method, boundaries and privacy

Generated from sanitised, aggregated records. No prompts, responses, transcript paths, account identifiers, API keys or precise working timestamps are published. See the privacy disclosure.
