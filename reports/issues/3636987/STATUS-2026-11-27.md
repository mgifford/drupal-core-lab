## What the thread says

- Reporter (rkoller, 2026-11-10): caret position and size on selects differ between normal and
  forced-colours mode on `/admin/content`; steps use Edge DevTools Rendering with
  `prefers-color-scheme: dark`, `forced-colors: active` and `prefers-contrast: more`.
- mherchel (2026-11-14): the theme uses `appearance: revert` so the native chevron follows the user's
  colour scheme.
- A system comment on 2026-11-14 says "Now that this issue is closed", so the issue had been closed.
  Comment #5 (2026-11-14) then reports two carets on every select on current `main`, and comment #6
  (2026-11-20) reproduces the duplicate chevron, identifies the specificity conflict and attaches the
  patch. The issue is Active again with its last status change on 2026-11-20; the API response the lab
  reads does not include the reopen event itself.

## Current proposal

Attachment 7210257 adds `.dark-mode .form-element--type-select` to the `@media (forced-colors: active)`
selector list in `core/themes/default_admin/css/components/form--select.pcss.css` (and the compiled
`form--select.css`). The declaration block is unchanged (`padding-inline-end`, `background-image: none`,
`appearance: revert`); no `!important` and no SVG change. The lab imports it unchanged; see
[BRANCHES.md](BRANCHES.md).
