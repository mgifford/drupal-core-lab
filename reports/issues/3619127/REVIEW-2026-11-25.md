## Why the MR is not ready as pushed

The MR itself is not the stack that passed:

1. **jQuery dependency.** The MR adds `core/jquery` to the `sidebar` library and uses `$target.parents(...)`. This is the
   unresolved frontend-framework-manager question (mherchel/larowlan). The lab’s `patch-0-vanilla-js-no-jquery.patch` removes it
   with native `closest()` and drops `core/jquery`.
2. **Saved preference is overwritten.** The fragment handler calls `showSidebar()` without the non-persisting argument, so
   opening the sidebar from an error link changes the user’s saved open/closed preference. `patch-1` fixes this.
3. **Fixed test sleep.** The test uses `$session->wait(500)`; `patch-1` replaces it with condition-based waits.
4. **Base is stale relative to current `main`.** The MR head is from 2026-09-17 and the lab’s evidence is from 2026-10-01.
   It is mergeable now, but it has not been re-tested on current `main` or re-run for the new core.
5. **Frontend framework manager review is still a stated tag/decision.** The lab cannot make that call.
