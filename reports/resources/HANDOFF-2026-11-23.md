# Resource attribution handoff (2026-11-23)

This is a working handoff, not a claim of completed efficiency work. It covers the first bounded stage: audit, classifier
and provenance foundations, request-level accounting, exploration diagnostics, reporting and tests. It does not claim
that any Drupal accessibility work became faster or cheaper.

## What changed and why

| Area | Change | Why |
|---|---|---|
| Classification | New versioned rule registry (`tools/resource/rules.mjs`); `classify.mjs` classifies operations, not command labels | A tool label such as `Bash/node` or `Bash/git` does not say what happened. Rules now separate tool name, script registry, parsed command and inline-code signals. |
| Unknown | Reason codes, rule ids, provenance and confidence on every classification | Unknown is now explainable and reproducible; it is not silently relabelled. |
| Request accounting | `session-usage.mjs --requests`; one `ai-request` event per provider message id; session roll-up | Session tool-call-share was too coarse. Request-level usage reconciles exactly with session totals. |
| Reconciliation | Deterministic match/mismatch, duplicate-record counts, tool-free and multi-tool counts | No silent adjustment; uncounted roll-ups cannot be double counted. |
| Prompt provenance | Metadata-only prompt capture (origin, purpose, content types, size, fingerprint, artifact references); opt-in raw local content | Answers “what was asked?” without publishing prompts. |
| Artifact provenance | Bounded ZIP central-directory inspection and patch metadata; no extraction, no execution, no symlink following | ZIP/patch size is not model ingestion; the system records that distinction. |
| Exploration | Subcategories, local lookup targets, repeated/after-edit/after-failure diagnostics, `code-map` use | Repetition is a diagnostic, not automatically waste. |
| Tasks | Local explicit task records, task fields on events, task-effectiveness view and `resource-task` command | A session id is not a development task; a completed claim is not a verified outcome. |
| Reporting | Attribution quality, Unknown reasons, reconciliation, task effectiveness, exploration, prompt composition and methodology sections | The dashboard and report now expose measurement quality separately from token totals. |
| Audit | `node scripts/resource.mjs audit [--json]`; `reports/resources/ATTRIBUTION-AUDIT.md`; `METHODOLOGY-COMPARISON.md` | Repeatable investigation without a model call. |

The token total did not change: 812,783,208 provider-reported tokens, with 2,181 Claude requests (plus 54 model-eval
requests) and 10 of 10 sessions reconciled. See [METHODOLOGY-COMPARISON.md](METHODOLOGY-COMPARISON.md).

## What passed, what remains uncertain

Passed and measured:

- 10/10 request-level sessions matched; 2,181 request events equal 812,265,879 session tokens; 0 missing usage; 2,740
  duplicate usage records collapsed.
- Activity coverage: 1,956/2,348 counted events (83.3% of events and tokens); model requests 1,843/2,235 (82.5%);
  tool operations 92.4% inside a classified event.
- Unknown: 392 events, 135,999,107 tokens (16.7%). Reasons: `model_only_request` 231 events/81.0M; `compound_command`
  137/45.0M; `unrecognized_command` 24/10.0M.
- Exploration: 502 unique targets, 49 repeated targets, 82 repeated lookups, 61 failed searches, 32 after a failure, 5 after an edit, 21 loop-like sequences, 27 `code-map` calls.
- Prompt metadata: 239 prompts, 493,684 bytes, 11 repeated prompts within a session, 169 artifact references, none
  inspected by default. 207 human / 32 generated.
- Re-import is idempotent.

Not verified:

- **Manual keyboard and screen-reader review.** The automated dashboard run now covers the new tables in six contexts
  (including 320 px and 200% text) with 0 axe violations, and found and fixed a real reflow defect. Automated checks do
  not establish complete accessibility conformance: a person still needs to do a keyboard-only and screen-reader pass,
  and forced-colours was checked by emulation, not on a real high-contrast display.
- **Prompt content/artifact inspection on real ZIPs.** No real ZIP attachments were present in the local transcripts;
  ZIP/patch inspection is covered by synthetic fixtures only.
- **Task outcomes.** A local explicit-task layer now exists (`scripts/resource-task.mjs`, task fields on events and a
  public task-effectiveness view). One local task record exists (`issue-3619127`, `completed_verified`, verified by the
  owner, no mapped session), so the task view shows it with zero resource attribution and `data_completeness:
  unavailable`. A session maps to at most one task, and unsuccessful-iteration signature detection is not implemented.
  The next step is to map the actual session; a verified outcome without resource events is legitimate but must not be
  read as zero consumption.
- **Other clients.** Only Claude Code transcripts are adapted. Codex, Cursor, direct API clients and local models have no
  adapter.
- **Latency separation.** Session API/tool duration is available; per-request duration, CI queue time and human pauses
  are not. CPU time remains measured only for wrapped commands.
- **Budget enforcement.** No new enforcement was added. New diagnostic ideas remain opportunities, not budgets.
- **Historical reclassification.** The archived summary is preserved; request-level events were added only for the local
  transcripts that still exist. Old session rows are labelled legacy.
- **Privacy review.** The public allowlist passes and prompt text is not in the export. A human privacy review is still
  required before publishing a new dashboard build.

## Requires human review

- The public dashboard content and privacy boundary (prompt metadata aggregates, issue attribution, session grouping).
- The rule registry, especially the primary-operation precedence and the inline write/read/test signals.
- The methodology comparison; it must not be read as an efficiency claim.
- Whether any proposed workflow change (code-map use, narrower commands, new session handoffs) is worth adopting.

5. Only then run a controlled comparison (same model, task complexity, starting revision/context, tools, environment,
   deliverables) and report cost/time per verified outcome.

## Reproduction and rollback

```bash
node scripts/resource.mjs audit
node scripts/resource.mjs collect --source=claude
node scripts/resource.mjs report --write --baseline
node scripts/resource.mjs report --check
node scripts/build-cloud.mjs
node scripts/selftest.mjs
```

The archived baseline is untouched. Reverting this change restores the previous classifier and session-level reports;
delete the local ledger only if you intend to discard the new request-level measurements.
