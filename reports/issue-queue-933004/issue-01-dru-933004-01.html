Summary

Introduce a non-growing baseline that records core form elements rendered without an accessible #title, so MR !7659 can land safely without regressing the existing surface.

Description

MR !7659 (nicxvan) grew in scope. Before adding titles to ~140 elements we need a guard: a static detector + a committed baseline list that fails if it grows. Part 1 ships the detector and an initially-empty baseline; later parts fill the baseline per component and add titles.

Steps to reproduce

  1. Install core from the branch containing FormElementTitle.
  2. Run FormElementTitleBaselineTest.
  3. Inspect core/modules/system/tests/fixtures/form_element_title_baseline.txt.

Expected result

Test seeds an empty baseline on first run and fails loudly if the count of unlabeled elements increases on later runs.

Actual result

Today there is no guard; adding titles is done ad hoc per element with no regression protection.

Testing environment

  • Drupal 11.x (post core update to upstream/main dcce147d40).
  • PHPUnit Kernel test (no browser required).
  • Env var FORM_TITLE_BASELINE_SEED=1 regenerates the baseline.

Impact

Prevents future regressions and gives reviewers a finite, auditable list of elements still needing titles.

Suggested fix

Use FormElementTitle::collectMissingTitles() in a Kernel test that compares against the committed baseline fixture; fail when the set grows.

Scope

  • Detector helper + baseline test + empty fixture.
  • No titles added yet (those come in later parts).

Out of scope

  • Adding titles to individual elements (Part 2+).
  • Runtime deprecation (Part 8).

Open questions

  • Should the baseline live in core/lib or web/modules/custom?
  • Should the detector run in CI or only on demand?
